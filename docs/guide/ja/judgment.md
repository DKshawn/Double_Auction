# Judgement under Uncertainty

[日本語](../ja/judgment.md) · [中文](../zh-CN/judgment.md) · [English](../en/judgment.md)

出典は旧 Judgment 単独版（旧名 `DKshawn/Exp-all-in-one`）、実装は `src/experiments/judgment/` です。[固定した出典と変更点](../../../src/experiments/judgment/UPSTREAM.md) を参照してください。

1. 実施可能な14課題から選択し、課題順・選択肢順のランダム化を別々に設定します。各課題の丸い **i** ボタンで、説明・所要時間の目安・実施条件を確認できます。クリックしても選択状態は変わりません。選択前に全課題を自動選択することはありません。学生画面のプレビューは回答を保存せず、制限時間を停止します。
2. ルームを作り、学生にコードを共有します。学生は7桁の学生証番号（先頭の0を保持）と4桁の暗証番号で入室し、教員の開始を待ちます。
3. 教員が開始すると学生ごとに条件を割り当て、各自の進度で回答します。途中入室も可能です。条件・順序は保存され、再入室しても変わりません。画面の言語は日本語・中文・Englishから選択できます。
4. 五秒間の乗算推定は開始後に計時します。期限後の入力は採用せず、再読み込みなどの中断と無回答を記録します。会話課題は実際の相手の学生証番号で同じ実施回内の相互回答を照合します。
5. 教員は参加状況を確認し、実施を終了できます。その後、同じルームで課題を選び直して次の実施を開始できます。完了済みの回答は別の実施回として保持します。
6. CSVは回答ごとの行、全記録JSONは条件・乱数シード・課題全文・言語履歴・計測・実施履歴・会話ペア分析を含みます。全14課題の選択時は86ページです。

元のSQLiteサーバーは起動しません。共通のPostgreSQL接続に `judgment_*` テーブルを追加し、共通コード台帳に登録します。Vercel + Neon の接続設定は共通です。元アプリの既存SQLiteデータは自動移行しません。

検証: `npx tsx --test tests/judgment-platform.test.ts`。HTTP全工程は、隔離したローカルサーバーで `npx tsx scripts/verify-judgment-http.ts`（既定 `http://127.0.0.1:3200`、`JUDGMENT_TEST_ORIGIN` で変更）を実行します。検証用ルームを作成し、クラウド接続では実行しないでください。
