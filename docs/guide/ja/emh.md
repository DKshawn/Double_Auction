# EMH 資産市場実験

[日本語](../ja/emh.md) · [中文](../zh-CN/emh.md) · [English](../en/emh.md)

実装は `src/experiments/emh/`、ルールは `/emh/guide`、仮想参加者8人との練習は `/emh/demo` です。出典は [Session5-1（Exp1解説あり）.pdf](../../../material/emh/Session5-1（Exp1解説あり）.pdf) の実験1です。[実施条件と原資料との対応](../../../docs/experiments/emh.md) を参照してください。Session6-1 の実験2は参考資料として保存し、未実装です。

1. 実験名、教員パスワードと必要な教員用キーに加え、初期証券数（1〜20、既定2）、1市場の目標人数（3〜12、既定9）、タイプ1・2・3の人数比率（各1〜100の整数、既定1:1:1）、A・B各期の取引時間（1〜30分、既定4分、秒単位に丸めて保存）を設定します。ルーム作成後も受付中は編集でき、「設定を保存」で反映します。
2. 3人以上が入室したら予定人数を確認し、「分け方を確定して受付終了」を押します。全員をランダムに割り当て、各市場3〜12人、人数差は最大1人です。市場数は人数÷目標人数を四捨五入し、上下限に合わせて調整します。各タイプを最低1人確保し、比率から最も不足しているタイプに残りを配分します。同点なら全市場の偏りを小さくします。既定では28人を10・9・9人に分け、比率2:1:1で8人なら4・2・2人です。端数により実人数比は希望比率と一致しない場合があります。受付上限は999人です。
3. 確定時に条件・市場・個人のタイプを保存し、編集をロックします。再読込や開始操作で再抽選しません。開始前だけ「割り当てを解除」で確認して受付と編集を再開でき、再確定すると再割り当てします。「全市場で実験を開始」後は解除・条件変更とも不可です。市場の切替、全市場の一時停止・再開、選択市場の期終了は引き続き使えます。
4. 各ラウンドの初期保有は設定した数、総供給Qは市場の実人数×初期証券数です。A期保有をB期へ持ち越し、B期末で消滅。次のラウンドは同じ初期保有・売買収支から再開し、累積得点を保持します。初期配分の総配当は初期証券数×各タイプの実人数と配当の積の合計、最大配当はQ×当該期の最大配当です。配分効率は実際の総配当÷最大配当、改善分の効率は（実際−初期）÷（最大−初期）で、分母0なら空欄です。
5. 全6ラウンド、A/B期は設定した共通時間、1取引最大30秒、休憩60秒。連続2取引不成立で期末へ進むため、設定時間前に終わる場合があります。タイプ1〜3のA/B配当216/105、200/110、257/83は固定です。3タイプすべてが存在し、現金・保有上限を設けない現行条件では、表示する理論基準はA期340/367、B期110のままです。Demo Modelは従来の練習条件を使います。
6. 終了後に教員が解説を公開するまで、学生には他のタイプの配当・成績・理論価格を送りません。教師用JSONは希望比率、確定条件、確定時刻、実人数と個人別割り当てを保存します。結果CSVは実人数・初期証券数・総供給・各期秒数も含み、市場別／全市場を出力できます。学生CSVは本人のみです。旧ルームに設定項目がない場合は従来の既定値を適用し、確定済みの記録は再計算しません。

部屋コードは `lab_room_registry` で各実験にまたがって一意に管理します。既存の `auction_*` テーブルに加え、EMH は `emh_sessions`、`emh_markets`、`emh_command_receipts`、`emh_login_attempts` を使います。接続時の migration で作成・既存コード登録を行います。新しい接続文字列は不要です。各市場の行ロック、DB時刻、操作IDによる再送処理を使い、取得時にも期限を処理します。学生は自分の市場だけ、教員は全体と選択市場を取得します。正式な配当値はサーバー用ファイルに置きます。

統合版はローカルおよび公開済みの Vercel + Neon 環境で検証済みです。[移行・検証記録](../../../docs/releases/unified-platform-migration.md)を参照してください。旧 Judgment の SQLite データは取り込んでいません。ローカル用の検証には `LOCAL_ONLY=1` と別の `PGLITE_DATA_DIR` を指定し、`DATABASE_URL` と `LOCAL_DATABASE_URL` を空にしてください。既存のローカルDBを複数サーバーから同時に開かないでください。999人は受付上限であり、クラウドでの同時接続性能を保証する数ではありません。

サーバー起動中の HTTP 検証は `npx tsx scripts/verify-emh-http.ts`（既定 `http://127.0.0.1:3200`、`EMH_TEST_ORIGIN` で変更）。教員用キー未設定の独立したローカルDBで実行し、検証用ルームを作成します。

新規の検証：`tests/emh-engine.test.ts`、`tests/emh-platform.test.ts`。全人数の割り当て、30人の並列市場、私的情報、再入室、再送・同時約定、時計・全6ラウンド・配当・明示公開、両実験の共通コード・管理を検証します。

`tests/e2e/emh-settings.spec.ts` では、条件の保存・再読込、別画面との編集競合、確定・解除、8人での全6ラウンド、重複送信、個人情報とCSV/JSONをブラウザーから検証します。
