# 資産市場実験 / EMH

正式な統合版は隣の `Exp-all-in-one` プロジェクト、[DKshawn/Exp-all-in-one](https://github.com/DKshawn/Exp-all-in-one) の main で管理しています。[教員入口](https://exp-all-in-one.vercel.app/teacher)で DoubleAuction・EMH・Judgement under Uncertaintyを選び、[学生入口](https://exp-all-in-one.vercel.app)から参加できます。このフォルダーは原資料と単独版を保持しており、以下は単独版の説明です。

Session5-1 の実験1をオンライン化した授業用アプリです。Next.js / React / TypeScript、Vercel + Neon PostgreSQL に対応。UI は日本語です。

## ローカルで起動

Node.js 22 以上を使います。

```sh
npm install
npm run dev
```

- 参加画面：<http://127.0.0.1:3100>
- 教員画面：<http://127.0.0.1:3100/teacher>
- ひとりデモ：<http://127.0.0.1:3100/demo>

`DATABASE_URL` 未設定時はローカルの PGlite（PostgreSQL）を使用し、`.data/emh` に永続化します。再起動しても記録が残ります。同じ保存先を複数プロセスから開かないでください。開発サーバーと本番サーバーを同時に動かす場合は `PGLITE_DATA_DIR` を分けます。

デモは同じ市場エンジンを使い、あなた1人と仮想参加者8人で動作を確認します。配当・時間・ラウンド数はデモ専用です。DBには保存せず、再読み込みでリセットします。背景タブでは進行を止めます。仮想参加者は人間の学習や市場の収束を再現するモデルではありません。

## 実施方法

1. 教員画面で実験名、ラウンド数、時間、ルームのパスワードを指定します。作成前に配当を変更できます。
2. ルームコードまたは参加リンクを9人に共有します。教員は取引せず、リーダーの進行・記録を担当します。複数のグループでは別々のルームを作ります。
3. 学生は学籍番号（または研究用参加者番号）、名前、再入室用PINを入力します。PINは4〜8桁です。学生同士には番号だけを公開し、名前・学籍番号は公開しません。
4. 9人そろったら「実験を開始」。被験者番号1〜9をサーバーで無作為に割り当て、配当条件は全ラウンドで固定します。
5. A期 → B期 → 休憩 → 次のラウンドを自動進行します。教員は一時停止・再開、当期の終了、休憩の短縮を操作できます。
6. 終了後にCSVを保存します。「解説を公開」で初めて学生に全タイプの配当と理論価格を表示します。

再入室は同じコード、参加者番号、PINを使用します。教員は `/teacher` の「再入室」からルームのパスワードを使います。教員と学生のCookieは分離されており、同じブラウザーで両画面を開けます。異なる学生を同時に試す場合は別ブラウザープロファイルを使います。同じ参加者として別端末に再入室すると、古い端末の認証は失効します。

## 資料から採用したルール

出典：`materials/Session5-1（Exp1解説あり）.pdf`。もう一方の Session6-1（実験2）は今回の対象外です。

| 項目           | 実装                                       | 根拠        |
| -------------- | ------------------------------------------ | ----------- |
| 人数           | 教員1人 + 交易者9人                        | PDF p.9     |
| ラウンド・時間 | 6ラウンド、A/B各240秒、休憩60秒            | PDF p.10    |
| 取引単位       | 毎回1単位、最大30秒、連続2回不成立で期末へ | PDF p.10–11 |
| 初期保有       | 各ラウンド2単位、総供給18単位              | PDF p.8–9   |
| 私有配当       | 1–3番 216/105、4–6番 200/110、7–9番 257/83 | PDF p.17    |
| 証券の期限     | A期保有をB期へ持越し、B期末に消滅          | PDF p.8     |
| 売空           | 禁止、保有量は0以上                        | PDF p.6     |
| 得点           | 売却額 − 購入額 + A配当 + B配当            | PDF p.8–9   |

PDF p.5–7の論文紹介には7分・8ラウンドの設定もあります。既定値はp.9–11の**授業の実施手順**を優先しました。論文の条件を使う場合は作成時に変更できます。

オンライン化で明示した点：

- 買値は現在の最高買値より高く、売値は現在の最低売値より低く提示します。反対側の提示を受けるボタンは価格の一致に相当します。価格が交差した場合は**先に存在していた相手の提示価格**で取引成立します。
- 価格は1〜100,000の整数。これは入力上の上限で、資料の資金制約ではありません。現金の下限は設けていません。
- 指名は最初の提示の依頼で、指名者以外の取引を禁止しません（p.11「だれでも自由に」）。
- 各取引成立・取引時間切れで両方の提示をクリア。個人は自分の最良提示を取り消せます。
- A期末の配当はその時点の持分で計算し、B期では再び売買できます。次のラウンドの持分・売買収支・配当はリセットし、確定得点だけ累積します。
- 全員切断していても期限はDBに残ります。次の読取・操作時に元の期限で順に進行を復元します。サーバー常駐タイマーやVercel Cronは不要です。

## 指標とデータ

既定値の理論価格は A期の私的情報均衡340、A期の完全予見均衡367、B期110（PDF p.15–18）。配当を変更すると理論値も再計算します。教員だけに表示し、学生には終了後の明示公開まで送りません。

以下は別の指標として保存します。

- `priceRatio` = 平均取引成立価格 / 当期の完全予見均衡価格。無取引成立は `null`。
- `allocationEfficiency` = 実際の総配当 / 最大総配当。
- `gainEfficiency` = (実際の総配当 − 初期配分の総配当) / (最大総配当 − 初期配分の総配当)。取引なしで0、配当同一で分母0なら `null`。

PDF p.21の日本語注記は価格/PFと説明していますが、引用表の脚注は初期配分からの改善分を基準にしています。そのため両者を混同せず、価格比・配当比・改善分効率を別々に出力します。

教員のCSV：取引成立、期別結果、個人別配当、参加者、操作記録。実験条件はJSON。学生のCSVは本人の売買と配当だけです。時刻はUTCのISO形式、CSVはUTF-8 BOM付きでExcelに対応し、文字列の数式注入を防止しています。条件JSON・CSVにパスワード、PINハッシュ、セッションキーは含めません。

## Vercel + Neon

この段階ではローカル開発のみ。VercelプロジェクトやNeonリソースは作成していません。

| 環境変数             | 用途                                                           |
| -------------------- | -------------------------------------------------------------- |
| `DATABASE_URL`       | Neonのpooled PostgreSQL接続文字列。Vercel上では必須            |
| `TEACHER_ACCESS_KEY` | 教員の設定画面とルーム作成を保護する共通キー。Vercel上では必須 |
| `PGLITE_DATA_DIR`    | ローカル保存先。任意、既定 `.data/emh`                         |

VercelのNext.js設定で `npm run build` を使えます。Neonのリージョンに合わせてVercel Functionsのリージョンを選択してください。Previewには独立したNeonブランチを使用します。接続時に `emh_` 接頭辞の3テーブルを初期化します。手動実行は `.env.local` を用意して `npm run db:migrate`。

オンラインでは環境変数が不足してもローカルDBへフォールバックしません。Neonの読取にはHTTPドライバー、変更にはリクエスト内で完結するWebSocket接続のトランザクションを使います。詳細は [Neon Node.js documentation](https://neon.com/docs/guides/node) と [Next.js Route Handlers](https://nextjs.org/docs/app/api-reference/file-conventions/route) を参照。

サーバーでルーム行をロックし、DB時刻で締切判定、持分の移転、取引成立、配当を同一トランザクションにします。各操作にはリクエストIDを付け、DBの一意制約で再送を重複処理しません。学生には `RoomView` の許可済み項目だけを返します。正式な既定配当はサーバーコードに置き、公開JavaScriptへ含めません。教員設定の初期値も教員キーによる認証後だけ送ります（キー未設定のローカル開発は除く）。

同期は取引中1秒、待機・休憩中2秒、完了後6秒のHTTPポーリングです。実験時計はサーバー側で権威を持ちます。1市場9人を前提とした構成で、学内全体の多数市場によるNeon/Vercel負荷試験は未実施です。

## 検証

```sh
npm run typecheck
npm test
npm run build
# 開発サーバーを起動した状態で、ローカルAPIの完全な実験を確認
npm run test:http
```

`test:http` はloopback宛てだけを許可し、`HTTP検証用` というルームを作ります。9人の入室、認可、個人情報の非公開、重複取引成立防止、一時停止、2ラウンド分の配当、全エクスポート、PINでの復帰、別オリジンからの拒否を確認します。本番のNeon接続は別途環境変数を設定後に確認してください。
