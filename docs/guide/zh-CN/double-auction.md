学生等待画面使用统一的卡片设计，并保留各实验的信息。

[Demo Model](https://exp-all-in-one.vercel.app/demo) · [演示操作](demo.md)

屏幕尺寸演示可通过 `/demo/preview` 打开；窄屏使用下拉框切换尺寸，演示进度会保留。

设置页的页眉提供「戻る」；从已有房间打开时，还会显示「ルーム … に戻る」。Demo 设置页使用页眉的「戻る」返回演示列表，或使用「教員用ページへ」返回教师页面。

CDA 和 EMH 共用可切换「一覧」和「棒グラフ」的订单板，两种视图都会标出自己的有效报价。CDA 原有的价格和时间优先、订单深度、数量及撤单规则保持不变。

## 按实际参加人数分配

可以先创建房间，在等待学生加入时继续设置。指定希望的市场数，使用「締切タイマーを開始」（5至3600秒）或「入室を締め切って割り当て」关闭加入。截止以保存的服务端时间判断；即使浏览器关闭，下一次加入或重新连接时也会拒绝截止后的新参加者。关闭加入本身不会开始实验。

手动指定市场数时，实际建立的市场数为希望数量与 `floor(N / 2)` 中较小者，N 为截止时参加人数，各市场人数最多差1。自动模式按每市场16人依次分配；最后只剩1人的市场需要等待补充。奇数人数也可全员参加，注册上限999人。供需模板人数会向上取到最大市场人数对应的偶数；999人集中在一个市场时使用1000人的模板。开始前可通过「入室を再開」保留同一代码重新开放加入和分配。

模板价格和生成参数不变，按各市场买卖双方的实际人数均匀抽取或复制已有条件。市场均衡、最大剩余和效率根据实际价值、成本计算。人数不同的市场可能有不同曲线，可使用条件 JSON 的 `config.studyLayout`、`markets[].schedules` 和 `marketEquilibria` 比较。相同人数、加入顺序、市场数和种子会得到相同席位与角色；奇数市场多出一人的角色也由种子决定。制度顺序另行随机分配。

教师可在名单点击「参加終了」确认退出。开始前退出者不再参与分配；若已分配则重新开放加入，接收期间的截止计时器仍继续。开始后退出会取消该学生未成交订单、买单和剩余报价库存，保留已成交记录、利润、角色和开始时的均衡基准，其他人继续。短暂断线或重连不会视为退出。当前不支持撤销退出或开始后新增参加者。

`admission-updated`、`admission-closed`、`participant-withdrawn` 记录接收设置、截止时间、实际人数、最终分配、退出和取消对象。未开始的旧固定人数房间可用「人数を確定せず入室を受け付ける」切换；进行中和已结束房间的市场构成不变。记录追加到现有 JSON 存储，不需要修改认证或迁移生产数据。

## 实验构成

- 学生昵称最多7个字符。等待页显示选定制度、各制度期数及总期数。每个市场在制度的最后一期结束后统一查看结果8秒，再切换制度；最后一个制度的结果展示后结束。旧房间未保存期数时保持每制度5期。
- 标准条件模板为8名买方和8名卖方。自定义模板使用偶数人数，不限制实际加入人数。每种制度可独立设置每人1至5单位（默认2），只向学生显示当前1单位的价值或成本，成交后进入下一单位。可选1至3种制度，每制度1至20期（默认5），开始前仍可修改。
- 角色、所属市场、各单位的价值与成本在全部期间固定，每期开始恢复该制度的可交易数量。CDA 成交后显示下一单位和清空的价格输入框，并保留输入焦点。
- 创建前的人数预设用于条件模板和希望市场数，也决定演示的虚拟参加人数初值。正式实验无需达到固定人数，接收加入期间可以修改市场数，不使用虚拟参加者补足缺额。
- 多市场尽量均衡分配所选制度的全部排列，各排列分配次数最多差1。单市场按 CDA、Call、Posted Offer 的顺序剔除未选制度。各制度的期数按该市场实际顺序累加。
- 新加入者先按加入顺序列在等待名单，关闭加入后显示分市场名单。开始前可重新随机分配，每市场买卖人数最多差1，无需等待固定预计人数到齐。
- 「実験を開始」在全部市场显示共同的5秒倒计时，倒计时结束开始第1期。学生在等待时看不到暂定条件，倒计时期间不能交易。此后市场独立自动推进；暂停、恢复、结束当前期和结束实验作用于全部市场。旧保存房间保留原来的加入和开始方式。
- 条件 JSON 保存加入时间、加入顺序和最终分配。固定人数房间重新抽签记录为 `participants-randomized`，自由加入房间关闭和重新分配记录为 `admission-closed`。预计开始时间记录为 `start-countdown`，每市场实际开始为 `period-started`。
- 教师的「全市場の結果」把各市场当前期与绿色剩余时间标签放在同一列。默认统计当前期；选择历史期时，数量、价格、指标和统计制度切到所选期，当前进度、时钟和状态仍显示实时值。
- 系统管理成交、时钟、清算、购买顺序和记录，不设置学生主持人。
- 学生只看本人的条件、所在市场当前制度全部已配置期数的价格、订单和个人交易，最近成交价和明细也使用相同范围。切换制度时切换历史范围，累计利润仍涵盖所有已实施期。教师保留全期记录，可按全部期间或各制度比较价格图。理论均衡与全体条件仅教师可见；该显示约定记录在 `rules.studentHistoryDisplay`、`rules.teacherHistoryDisplay`。
- CDA 订单簿显示有效买卖订单和最近成交价，标准16人市场双方各8行。「注文履歴・歩み値」使用中央独立列，条件与下单表单位于订单簿下。历史把当前制度所有已结束订单和成交按时间及事件顺序倒序合并为一张表，以买单、卖单、成交区分；已成交订单并入对应成交行，避免重复。学生不看参加者编号，本人记录标为「あなた」；教师保留编号。新行和数量用淡绿色闪烁两次，共2.4秒，初始或未变化记录不闪烁；减少动态效果时仅短暂显示绿色背景。历史在表内滚动，「最新」回到顶部，不用分页或标签切换。历史不能交易，不参与最优订单、撮合或价差计算。CDA 立即成交订单的输入限价不进入公开历史。Call 接收期间显示有效订单，历史保留清算结果。结束的订单同时记录在 `order-closed` 审计事件及 `settings.json` 的市场级 `orderHistory`，公开规则见 `rules.cdaOrderHistory`。旧房间仅从更新后结束的订单开始记录历史。

本实现对应 `大規模実験メモ.pptx` 新版实验1，不采用旧口头实验的9人、主持人及手续费规则。原材料未唯一规定的操作选择在下文、教师页面与条件 JSON 中注明。该原材料不随仓库分发。

## 交易规则

教师可以在「実験時間の設定」分别设置 CDA 每期、Call 每次接收、Posted 卖方报价和买方共同交易时间，均为1至3600秒整数。创建后可在「実験設定を変更」中的同一设置处于开始前修改。Call 标准每期4次接收，设置5单位时为5次，接收时间可设5秒；不会统一改变已有房间的时间。未设置共同交易时间时沿用 `buyerSeconds × 市场买方人数`。设置保存到 `config.studyTiming` 和条件 JSON 的 `rules`，变更记录为 `study-timing`。

| 制度         | 默认时间                             | 订单与价格                                                                                                                   |
| ------------ | ------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------- |
| CDA          | 每期180秒                            | 每人1笔当前1单位订单；价格优先，同价时间优先。买卖交叉时按先在订单簿中的价格成交，替换订单失去时间优先权                     |
| Call Market  | 每期30秒×4次，5单位时为5次           | 每次为当前1单位提交1笔公开报价，仅截止时集中清算；按买价降序、卖价升序最大化可成交数量，全部按最后一对成交买卖价格的中点清算 |
| Posted Offer | 报价60秒及共同交易80秒，标准16人市场 | 卖方首次1单位报价在截止前不公开，成交后可再报下一单位；买方在报价列表点击购买，立即接受该卖方报价成交                        |

- **允许亏损交易**，界面显示预计利润。Commission 是每成交1单位额外支付给买卖双方的实验奖励，默认双方各1日元，设为0关闭奖励。按当前供需计算上限：将价值降序、成本升序排列，第一笔负剩余单位的差额为g，则须满足 `2 × Commission < g`，整数上限为 `ceil(g / 2) − 1`，且不超过999。没有负剩余单位时最多999。Default 和 `p=80, K=8, L=4, d=4` 的候选条件上限均为3。超过上限直接拒绝，不截断；人数、生成或手动条件变化也执行同样校验。开始前可在供需设置中修改，开始后固定。奖励显示在等待页和条件栏，并计入预计利润、成交通知、个人历史、当期及累计利润；未成交、取消或仅报价不获得奖励。旧房间和旧成交缺少该设置时保持0。每笔成交保存奖励值，后续设置变化不重算历史利润。价格、价值、成本和利润均为实验日元（JPY），不进行真实支付。
- 宽屏创建页按实验设置、供需条件、全部单位数值分为三列；1100px及以下将实验设置放在上方。供需和单位表区域宽度达到800px时单位表放右侧独立面板，否则放在下方。右表随滚动保持可见，大量单位在表内纵向滚动。供需预览同时显示无奖励和含奖励的均衡价格、数量，含奖励均衡按 `D+c`、`S−c` 计算；曲线、最大剩余和效率仍基于原始价值与成本。条件和奖励可在开始前一起保存。
- 输入报价必须为1至99999日元整数；Call 清算价可能为0.5日元刻度。
- Call 每人每次仅交易当前1单位。同价按每次清算随机抽取的参加者优先顺序处理并记录抽签。成交则进入下一单位，否则下次继续同一单位。
- Call 未成交订单每次清算后失效，可重新提交剩余数量；**清算不会恢复已交易数量**。
- Call 不选择数量。截止前没有提交即该次无订单，剩余数量和利润不变；仅输入不会自动提交，下次仍可下单。记录无法判断未提交的原因。旧版的 `call-pass` 作为历史审计记录保留。
- 新 Posted 使用 `studyPostedMechanism: direct-purchase-v1`，买方不填价格，从升序报价列表选择卖方。`posted-buy` 仅传报价ID和数量，服务端核对报价、剩余库存后立即成交。同一库存按服务端收到请求的顺序处理，拒绝重复购买、超库存和超可交易数量；重试不会重复成交。没有买方报价或每秒竞价清算。
- 旧房间 `batch-bids-v1` 保留原每秒按买价优先、同价抽签的机制；更早没有标记的房间保留随机顺序购买。既有实验不在中途切换机制，新机制请创建新房间。条件 JSON 保存机制和优先规则。
- 新 Posted 双方逐单位交易。卖方首次成交后可在共同交易期内重新报价下一单位，报价立即公开；买方成交后看到下一单位价值并可继续购买。等待再报价导致暂时无库存不会结束当期。截止前没有确认报价则当期不出品。旧版多单位或0单位报价继续作为历史操作记录保留。
- 中途结束取消未成交订单，并把进行中期标为 `interrupted`。Call 尚未清算的订单不成交，已正常结束的期仍为 `complete`。
- 标准16人市场的默认均衡为80日元，正剩余数量10，含零剩余的上限11，最大总剩余440日元。数量比、效率与价格偏差均按实际人数和价值、成本计算。

## 自定义阶梯供需

创建前的详细设置第2步为人数与市场，第3步「供需プリセット」为单位数、Commission 和供需条件。Default 按人数、单位数均匀抽取或复制既有 PPT 条件；自定义则由p、K、L、d生成另一组阶梯供需。教师演示共用表单，但 Default 为练习条件。预览随输入更新，点击一次「設定を保存して閉じる」保存；随后进入关闭加入的步骤。

创建后、开始前也可在「実験の準備」的「市場・取引条件」修改。Default 和自定义都通过一次「確定して次へ」保存当前条件并进入下一步。API 接收生成参数，服务端重新生成、校验后保存。传给学生的一般房间设置不包含生成参数、种子和分配表。

自定义初始候选为 `p=80, K=8, L=4, d=4`。从 Default 切换时回到该候选，重新打开已保存自定义设置则恢复保存值。改变人数、单位数不自动调整价格、K或L。第k单位的价值/成本分别为：

- k≤K：`p±d(K+1−k)`。
- K<k≤K+L：p。
- 其后：`p∓d(k−K−L)`。

K、L均为至少1的整数，K+L不得超过一侧总单位数，d>0；生成值必须为1至99999日元整数。条件不匹配时提示错误并禁止保存，不四舍五入或截断。

标准正式 Default（16人、每人2单位）的排序后曲线等同于 `p=80, K=10, L=1, d=4`，但分给每名学生的两单位组合不同。扩展至100人的 Default 会在均衡价格以外出现同价台阶，当前固定正价格差d的公式无法完全复现；Demo 的 Default 价差也不固定。没有用该公式替代原 Default。

输入时同步更新阶梯图、全部单位表、均衡价格与数量上下限、正/零剩余单位数、最大总剩余及学生分配候选。第k单位水平段覆盖数量k−1至k。初始候选在一侧16单位时均衡为80日元、数量8至12、最大总剩余288日元。L为1、4、6时，数量上限分别9、12、14；价格、正剩余数量和最大剩余不变。

图表以原始均衡价格及数量区间中点为中心，初始只展示附近范围。「拡大」「縮小」保留中心和线性尺度，「全体」显示全部单位，「初期表示」恢复。数量0以下或总单位以上只显示不同背景、不画曲线。右侧表格在屏幕高度内独立滚动，聚焦后也可用 PageDown、End。

一侧N人、每人U单位时，将排序后的第i、第i+N、…、第i+(U−1)N单位分给同一角色。相同人数市场使用相同角色条件；人数不同则均匀抽取或复制模板。同一参数按各制度的单位数生成条件，检查所有制度价格范围与 Commission。单位数保存在 `config.studyUnitCounts`，各制度供需保存在 `conditionsByInstitution`。新格式逐单位下单，旧房间保留原数量与订单规则；开始前保存供需设置会切换为新格式。

使用 Mulberry32 和 Fisher–Yates 打乱所有市场的固定席位，再按加入顺序分配学生。相同人数、加入顺序及0至4294967295的整数种子产生相同分配，候选种子默认为123456。已保存房间的种子不会自动改变。

点击「確定して次へ」前不改变房间条件。保存时服务端重新生成、核对，写入既有价值与成本字段；然后关闭加入，核对实际人数分配。旧固定人数房间使用「ランダムに割り当て」。同种子产生同分配，如需重抽，请在开始前修改种子、预览并保存。设置 JSON 的 `generation` 包括候选参数、种子、应用和确认时间，以及最终参加者ID、姓名、市场、席位、角色、单位、价值与成本分配。开始后条件与分配固定跨全期、全制度。手动编辑或恢复 PPT 条件会清除生成元数据。

均衡数量作为区间处理，零剩余交易使 `Q/K>1` 不会自动判为过量或低效。最大剩余为排序后各单位正价值减成本之和，效率为实际剩余与其之比，低效交易按价值小于成本计数。正式使用的L及种子复用规则由教师决定。

## 收敛指标与导出

没有强制价格向均衡收敛的处理。教师可按市场、制度、期查看和导出：

- 平均价格、距均衡价格区间的平均绝对距离。
- `α = sqrt(mean((价格 − p*)²)) / p*`，p*为均衡区间中点，显示为比率而非百分数；Call 包括各次清算中的个别成交并按数量加权。
- α随各制度所设期数变化的 OLS 斜率，只使用正常完成且有成交的期，同时记录所用期数。这是描述统计，不是显著性检验或自动收敛判断。
- 成交数量与 `Q / Q正剩余`，零剩余交易可能使比值超过1。
- 实际总剩余、相对最大总剩余的效率，以及价值小于成本的低效交易数量。
- CDA 最优卖价减最优买价的时间加权均值，仅计双方都有订单且未暂停的时间，并导出观察时长。

无成交的价格统计、分母为0的比例、没有观察时间的价差记为 `null`，界面为「—」，CSV 留空。剩余为价值减成本，不含 Commission，不把负值截为0；均衡、最大剩余与效率的供需基准不变。另行导出 Commission 支出总额和含奖励的参加者利润合计。

交易 CSV 含市场、制度、全局期、制度内期、清算次数、双方单位编号、价值、成本、含奖励及不含奖励的利润、每侧每单位 Commission。另有汇总 CSV、操作日志 CSV 和条件 JSON。导出时间为 UTC，页面显示日本时间。条件 JSON 包括各市场制度顺序、条件、规则、期完成状态、清算结果及指标，不导出认证信息。
