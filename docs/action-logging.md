# 学生操作日志

教师端新增「操作明細 CSV」。旧的订单、成交和「操作ログ CSV」保持可读，不回填或猜测历史按钮操作。

## 记录含义

- 按钮触发时记录端末时间、服务器时钟偏差、页面经过时间、按钮编号、市场、期数和阶段。鼠标点击、键盘提交和禁用按钮上的指针尝试分别处理。
- `study-quote` / `quote` 表示提交报价；`study-accept` / `accept` 表示接受最优订单。报价立即成交时仍归为提交报价。
- 成功只记录 `result`（报价受理、成交价格/数量/编号等），不填写 `errorCode`、`reason`。拒绝记录错误代码和提示原因，不生成成功结果。
- `unconfirmed` 不等于失败。响应丢失后按 `requestId` 只读查询；CSV 以服务器已提交的事件为准。
- 界面按钮的 `local_success/button_activated` 只证明端末触发了按钮，不代表交易成功。

## 数据与延迟

成功审计附加到现有事件 JSON，与交易同一事务保存，不新增成功路径 SQL 调用。网络重试沿用已有幂等规则，撮合顺序仍由服务器决定。

拒绝日志在市场锁释放后写入新的 `auction_action_logs` 表，避免随业务回滚丢失。未知通信/数据库异常保留为未确认。该表只存新增记录，不更新既有实验数据。

按钮日志先异步写入 IndexedDB，按房间和参与者隔离，每隔 6～10 秒批量上传，最多 32 条、约 28 KiB。下单不等待上传，下单期间暂缓启动新的定时上传。服务器按事件编号去重；收到确认后才删除端末待传记录。补传仅针对日志，不会重放交易。

上传接口使用学生 HttpOnly 会话，身份由服务器确定。客户端不能上传服务器结果、凭据或其他参与者 ID。完整操作明细只对教师开放。

操作明细导出/结果查询只执行读取，不触发结算或旧数据迁移。其他既有导出的行为保持原样。

端末时钟不保证准确，「クリック日時_サーバー推定UTC」「期開始から_推定ms」均为估计。清除浏览器数据、存储不可用等情况可能丢失尚未上传的点击。数据库不可用时也不能保证服务器异常记录立即落库。

## 独立验证

- `node --import tsx --test tests/action-log.test.ts`：新建内存数据库，验证结果/原因、命令区分、幂等、拒绝持久化、只读导出与身份隔离。
- `node --import tsx scripts/measure-action-audit.ts`：新建内存数据库，输出 SQL 次数与本地耗时。该耗时不能代表线上延迟。
- `node node_modules/@playwright/test/cli.js test --config playwright.action-log.config.ts`：独立临时数据库与构建目录，清空线上数据库环境配置，不复用已有服务器。可用 `E2E_CHANNEL=msedge` 选择已安装的 Edge。

浏览器测试覆盖日志上传阻塞时继续下单、校验失败、两种命令、服务器拒绝和刷新后补传。
