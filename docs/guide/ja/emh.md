# EMH 資産市場実験

[日本語](../ja/emh.md) · [中文](../zh-CN/emh.md) · [English](../en/emh.md)

学生の待機画面は共通のカードデザインを使い、実験ごとの情報を表示します。

実装は `src/experiments/emh/`、ルールは `/emh/guide`、人数・条件を設定して練習できるデモは `/emh/demo` です。出典は [Session5-1（Exp1解説あり）.pdf](../../../material/emh/Session5-1（Exp1解説あり）.pdf) の実験1です。[実施条件と原資料との対応](../../../docs/experiments/emh.md) を参照してください。実験2は [Session6-1](../../../material/emh/Session6-1（Exp2解説あり）.pdf) に基づきます。

価格・配当・売買収支・得点は画面上で円と表示します。

正式実験の設定画面は、ヘッダーの「実験を選び直す」から実験選択へ戻れます。デモは設定画面・デモルームとも、ヘッダーの「デモを選び直す」で一覧へ、「教員用ページへ」で教員のEMH設定へ戻れます。

開始操作後は学生画面の中央にDAと共通の5秒間の準備カウントダウンを表示します。学生は自分の条件を確認でき、カウントダウン終了後に取引と各期の時計が始まります。一時停止中はカウントダウンも止まります。実験1・2とデモに共通です。

## 実験1

1. 教員入口でキー認証後、実験名と教員パスワードに加え、初期証券数（1〜20、既定2）、1市場の目標人数（3〜12、既定9）、タイプ1・2・3の人数比率（各1〜100の整数、既定1:1:1）、A・B各期の取引時間（1〜30分、既定4分、秒単位に丸めて保存）を設定します。ルーム作成後も受付中は編集でき、「設定を保存」で反映します。
2. 3人以上が入室したら予定人数を確認し、「分け方を確定して受付終了」を押します。全員をランダムに割り当て、各市場3〜12人、人数差は最大1人です。市場数は人数÷目標人数を四捨五入し、上下限に合わせて調整します。各タイプを最低1人確保し、比率から最も不足しているタイプに残りを配分します。同点なら全市場の偏りを小さくします。既定では28人を10・9・9人に分け、比率2:1:1で8人なら4・2・2人です。端数により実人数比は希望比率と一致しない場合があります。受付上限は999人です。
3. 確定時に条件・市場・個人のタイプを保存し、編集をロックします。再読込や開始操作で再抽選しません。開始前だけ「割り当てを解除」で確認して受付と編集を再開でき、再確定すると再割り当てします。「全市場で実験を開始」後は解除・条件変更とも不可です。市場の切替、全市場の一時停止・再開、選択市場の期終了は引き続き使えます。
4. 各ラウンドの初期保有は設定した数、総供給Qは市場の実人数×初期証券数です。A期保有をB期へ持ち越し、B期末で消滅。次のラウンドは同じ初期保有・売買収支から再開し、累積得点を保持します。初期配分の総配当は初期証券数×各タイプの実人数と配当の積の合計、最大配当はQ×当該期の最大配当です。配分効率は実際の総配当÷最大配当、改善分の効率は（実際−初期）÷（最大−初期）で、分母0なら空欄です。
5. ラウンド数は1〜12、1取引と休憩は各1〜1800秒で設定できます（既定は6回・30秒・60秒）。A/B期は設定した共通時間です。連続2取引不成立で期末へ進むため、設定時間前に終わる場合があります。タイプ1〜3のA/B配当（円）216/105、200/110、257/83は固定です。3タイプすべてが存在し、現金・保有上限を設けない現行条件では、表示する理論基準（円）はA期340/367、B期110のままです。Demo Modelも同じ設定・確定手順・共通エンジンを使い、配当だけは練習用です。詳細は[デモの使い方](demo.md)を参照してください。
6. 終了後に教員が解説を公開するまで、学生には他のタイプの配当・成績・理論価格を送りません。教師用JSONは希望比率、確定条件、確定時刻、実人数と個人別割り当てを保存します。結果CSVは実人数・初期証券数・総供給・各期秒数も含み、市場別／全市場を出力できます。学生CSVは本人のみです。旧ルームに設定項目がない場合は従来の既定値を適用し、確定済みの記録は再計算しません。

## 実験2

正式ルーム作成時に「実験2」を選びます。1人あたりの初期証券数（1〜20）、目標人数（3〜999）、タイプ比率（各1〜100）、市場数（自動または1〜333）、連続不成立で終了する回数（1〜100）を設定できます。市場数を自動にすると実人数と目標人数から決めます。指定時は実人数を指定市場数に均等配分し、各市場に3人以上を配置できなければ確定できません。各市場に各タイプ1人以上を配置します。既定は目標12人、比率1:1:1、初期2単位、連続2回不成立です。ラウンド数は1〜6、各ラウンドは1〜30分、1取引と休憩は各1〜1800秒です（既定6回・5分・30秒・60秒）。証券は各ラウンド末に配当を払い消滅し、得点は売却額 − 購入額 + 配当です。空売りは禁止、資金制約はありません。

各状態の確率（合計100%）、各タイプ・状態の配当（0〜100000円）、各ラウンドの実現状態、内部情報の開始ラウンド（1〜7）と各タイプの人数（0〜999）を設定できます。内部情報の人数は各タイプの実人数を上限とし、確定前の市場プレビューに実際の人数を表示します。開始ラウンドが実施回数を超える場合や人数が0の場合は内部情報がありません。同じ対象者が以降のラウンドで情報を受け取ります。既定の確率は35/42/23%、正式実験の配当（円）は90/95/214、52/232/115、136/140/124、実現状態は1/1/1/1/2/2、第3ラウンドから各タイプ最大2人です。期末に状態を公開し、他のタイプの条件や均衡価格は実験終了後の解説公開まで学生に送りません。PI・RE均衡と効率は設定と実際の情報配分に基づいて計算し、条件と記録を保存できます。デモは1市場で別の練習用配当と状態を初期値に使います。画面サイズ別プレビューは `/emh/demo/preview` です。

EMHデモの操作パネルでは、教員・学生画面の切替、一時停止、30秒進める、次の期へ進む、やり直す、設定の見直しができます。時間を進めると仮想参加者の取引と期限も順に処理されます。カウントダウン中や一時停止中は早送りできません。「やり直す」は設定を保って割り当てと進行をリセットします。画面サイズ別プレビューでは操作パネルを枠外に表示します。

部屋コードは `lab_room_registry` で各実験にまたがって一意に管理します。既存の `auction_*` テーブルに加え、EMH は `emh_sessions`、`emh_markets`、`emh_command_receipts`、`emh_login_attempts` を使います。接続時の migration で作成・既存コード登録を行います。新しい接続文字列は不要です。各市場の行ロック、DB時刻、操作IDによる再送処理を使い、取得時にも期限を処理します。学生は自分の市場だけ、教員は全体と選択市場を取得します。正式な配当値はサーバー用ファイルに置きます。

統合版はローカルおよび公開済みの Vercel + Neon 環境で検証済みです。[移行・検証記録](../../../docs/releases/unified-platform-migration.md)を参照してください。旧 Judgment の SQLite データは取り込んでいません。ローカル用の検証には `LOCAL_ONLY=1` と別の `PGLITE_DATA_DIR` を指定し、`DATABASE_URL` と `LOCAL_DATABASE_URL` を空にしてください。既存のローカルDBを複数サーバーから同時に開かないでください。999人は受付上限であり、クラウドでの同時接続性能を保証する数ではありません。

サーバー起動中の HTTP 検証は `npx tsx scripts/verify-emh-http.ts`（既定 `http://127.0.0.1:3200`、`EMH_TEST_ORIGIN` で変更）。教員用キー未設定の独立したローカルDBで実行し、検証用ルームを作成します。

新規の検証：`tests/emh-engine.test.ts`、`tests/emh-platform.test.ts`。全人数の割り当て、30人の並列市場、私的情報、再入室、再送・同時約定、時計・全6ラウンド・配当・明示公開、両実験の共通コード・管理を検証します。

`tests/e2e/emh-settings.spec.ts` では、条件の保存・再読込、別画面との編集競合、確定・解除、8人での全6ラウンド、重複送信、個人情報とCSV/JSONをブラウザーから検証します。
