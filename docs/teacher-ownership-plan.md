# 教师身份与历史实验归属方案（待批准，未实施）

2026-10-13。用户决定：本次只整理方案，不修改认证、权限或生产数据库。

## 当前边界

- `TEACHER_ACCESS_KEY` 是共享的创建／房间管理密钥，不能识别不同教师。
- 每个房间的教师密码用于再入室；HttpOnly 的房间 Cookie 在服务端校验，数据库存储其哈希。
- `AuctionService.listRooms` 验证共享密钥后列出房间，尚无教师归属过滤。管理列表不是“我的实验”。
- 房间详情、操作、数据导出已有房间级教师凭证校验；其他房间的教师 token、学生 token、无效 token 均不能导出该房间。
- `/room/…?entry=teacher` 仅提示返回与重新登录入口，不能授予教师权限。

## 拟议实现

复用现有 PostgreSQL／PGlite 和密码哈希代码，不接第三方认证服务。增加：

1. `teachers`：独立教师 ID、唯一登录名、密码哈希、停用状态及创建时间。共享密钥仅用于管理员批准的开户流程，不能用于冒充任何教师。
2. `teacher_sessions`：随机会话 token 的哈希、教师 ID、到期时间、撤销时间。使用 HttpOnly、生产 Secure、SameSite Cookie；登录限速、密码修改后撤销旧会话。
3. `auction_rooms.owner_teacher_id`：可空的外键，另加按教师、创建时间查询的索引。新房间由认证后的服务端绑定创建者，不接受客户端提供的 owner ID。

服务端公共授权函数先认证教师会话，再校验房间归属；页面导航和前端筛选不参与授权。覆盖房间列表／搜索／历史、详情、实时 SSE、控制命令、设置、四类下载、恢复／删除接口。学生仍通过自己的房间身份进入，不能使用教师会话取得额外权限。历史下载可直接复用现有导出器，增加 owner guard 即可。

需要先确认旧房间密码再入室与新账号的过渡策略：建议新归属房间必须同时有所属教师会话，旧密码不能绕过归属；学生流程不变。教师密码的重置／账号恢复需要管理员流程，不能使用共享密钥直接接管历史房间。

## 旧房间兼容与迁移

- 所有旧房间保持 `owner_teacher_id = NULL`，绝不自动归入第一位登录者或某个默认教师。
- 未归属房间不出现在任何教师的“我的实验”，由管理员在独立审核入口核验实验名称、日期、现有房间凭证与实际教师身份。
- 经批准后以事务迁移，记录房间、原归属、新教师、审批者、时间、依据，保留可回退记录；不改交易、条件和审计日志。
- 本地准备迁移预览、备份／回退方案和隔离测试后，再单独取得生产迁移许可。本次未创建账户表、未添加归属字段、未迁移任何生产数据。

## 后续验收

教师 A/B 分别创建实验，互换 ID、Cookie、下载参数及 SSE 地址均无法访问对方实验；未归属实验不泄露给普通账号；过期／撤销会话失败；并发创建绑定正确；学生权限不变；搜索、总数和分页在 SQL 层过滤归属；CSV/JSON 与详情遵守同一授权函数。完成这些测试前不能宣称“每位教师的数据已隔离”。
