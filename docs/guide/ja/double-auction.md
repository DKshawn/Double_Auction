# Double Auction

[日本語](../ja/double-auction.md) · [中文](../zh-CN/double-auction.md) · [English](../en/double-auction.md)

学生の待機画面は共通のカードデザインを使い、実験ごとの情報を表示します。

[Demo Model](https://exp-all-in-one.vercel.app/demo) · [デモの操作](demo.md)

画面サイズ別デモは `/demo/preview` で開けます。狭い画面ではサイズを選択欄から切り替え、進行状況は保持されます。

教員入口でキー認証を済ませてから、ルームごとに8文字以上の教員パスワードを設定します。作成画面でキーを再入力する必要はありません。

設定画面のヘッダーには「戻る」があり、既存ルームから開いた場合は「ルーム … に戻る」も表示します。デモの設定画面では「戻る」でデモ一覧へ、「DEMOモードを終了」で教員設定へ戻れます。

CDA と EMH は「一覧」と「棒グラフ」を切り替えられる注文板を共用し、どちらの表示でも自分の注文を示します。CDA の価格・時間優先、注文の深さ、数量と取消のルールは従来どおりです。

## 人数を決めずに入室を受け付ける

新規ルームは先に作成し、学生の入室を待ちながら同じルーム内で設定できます。希望市場数を指定し、「締切タイマーを開始」（5〜3600秒）または「入室を締め切って割り当て」を使います。締切は保存済みのサーバー時刻で判定し、ブラウザーを閉じていても次の入室・再接続時に期限後の新規参加を拒否します。締切だけでは実験は始まりません。

手動指定では、締切時の参加対象人数Nで希望市場数と `floor(N / 2)` の小さい方だけ市場を作り、人数差が最大1人になるよう分けます。自動では16人ずつ順に割り当て、最後の市場が1人なら補充を待ちます。奇数でも全員参加でき、最大登録人数は999人です。供需テンプレートは最大市場人数を偶数に切り上げます（999人を1市場に集める場合は1000人分）。開始前は「入室を再開」で同じコードのまま受付・再割り当てできます。

条件テンプレートの価格・生成パラメータは変更せず、各市場の買い手・売り手それぞれの人数に合わせて既存の均等抽出・複製を適用します。実際の価値・費用から市場別に均衡・最大余剰・効率を計算します。人数が違えば市場の供需曲線も異なるため、条件JSONの `config.studyLayout`、`markets[].schedules`、`marketEquilibria` を比較に使ってください。シード指定時は同じ人数・入室順・希望市場数・シードから同じ席と役割になります（奇数市場の余分な側もシードから決めます）。制度の順序は従来どおり別に無作為割り当てします。

教員は名簿の「参加終了」で退出を確定できます。開始前なら割り当て対象から外し、割り当て済みの場合は受付を再開します。受付中の締切タイマーは継続します。開始後は未約定注文・買い注文・残り提示在庫を取り消し、成立済み取引・利益・役割・開始時の均衡基準を保存して他の学生は続行します。短い切断や再接続だけで退出扱いにはしません。退出を戻す操作・開始後の新規入室は今回追加していません。

`admission-updated`、`admission-closed`、`participant-withdrawn` に受付設定・締切時刻・実人数・最終割り当て・退出と取消対象を記録します。未開始の旧固定人数ルームは「人数を確定せず入室を受け付ける」で切り替えられます。進行中・終了済みの市場構成は変更しません。データは既存のJSON保存に追加するため、認証変更や本番データ移行は不要です。

## 実験構成

- 学生のニックネームは7文字以内。待機画面には実施する制度、各制度の期数、合計期数を表示します。各制度の最終期は同じ市場の全員が8秒間の結果確認を行ってから次の制度へ進み、最後の制度の結果確認後に実験を終了します。期数未設定の既存ルームは各制度5期を維持します。
- 条件テンプレートは標準で買い手8人・売り手8人。カスタムでは偶数人数で設定しますが、実際の参加者数を制限しません。CDA・Call Market・Posted Offerの1人あたりの単位数は、各制度でそれぞれ1〜5に設定できます（初期値2）。学生には現在の1単位の価値／費用だけを表示し、約定後に次の単位へ進みます。教員は1〜3制度を選び、各制度1〜20期を設定します（初期値は各5期）。制度・期数は作成後も開始前に変更できます。
- 役割、所属市場、各単位の価値・費用は全期間固定。各期の開始時にその制度の取引可能数へ戻します。CDAの学生画面は現在の1単位の価値／費用のみを表示し、約定後に次の単位と空の価格入力欄へ切り替え、入力フォーカスを保ちます。
- 作成前の人数プリセットは条件テンプレートと希望市場数を設定し、デモでは仮想参加者数の初期値にも使います。正式ルームの入室は固定人数を必要とせず、希望市場数は受付中に変更できます。不足人数を仮想参加者で補充しません。
- 多市場では選択した制度の全順列を、割当数の差が最大1になるよう無作為に配置します。1市場は CDA → Call → Posted Offer の順から未選択の制度を除きます。各制度の期数は市場ごとの順序に沿って加算します。
- 新規ルームは入室順の待機名簿に表示し、締切後に市場別の名簿へ切り替えます。開始前は再抽選でき、各市場の買い手・売り手の人数差を最大1人に保ちます。固定の予定人数がそろうまで待つ必要はありません。
- 教員が「実験を開始」を押すと全市場に共通の5秒カウントダウンを表示し、その終了時刻から第1期の取引時間を計測します。学生は待機中に暫定的な価値・費用を見ることも、カウントダウン中に取引することもできません。各市場は以降の期を独立して自動で進めます。一時停止・再開・途中終了・実験終了は全市場に適用されます。既存の保存済みルームは従来の入室・開始方式を維持します。
- 入室時刻・入室順・最終割り当てを条件JSONに、固定人数ルームの再抽選を `participants-randomized`、自由入室の締切・再割り当てを `admission-closed` 操作ログに保存します。開始の予定時刻は `start-countdown`、実際の第1期開始時刻は各市場の `period-started` に記録します。
- 教員の「全市場の結果」には、各市場の進行期と緑色の残り時間ラベルを同じ列に表示します。既定の集計対象は各市場の現在の期。過去の期を選んでも進行期・時間・状態は現在のまま、数量・価格・指標と集計制度を選択した期に切り替えます。
- システムが成立判定、時計、清算、購入順、記録を管理します。市場ごとの学生司会者は置きません。
- 学生には本人の条件と所属市場の現在の制度で設定した全期の価格・注文・個人取引履歴を表示。制度内の第1期から設定した最終期までを表示し、制度が変わると表示範囲を切り替えます。直近約定値と取引明細も同じ範囲です。累積利益は実施した全期の合計を保ちます。教員は実施した全期の記録を保持し、価格グラフを全期または各制度の設定期数に切り替えて比較できます。理論均衡と全員の条件は教員専用です。表示範囲はアプリの運用上の選択で、`rules.studentHistoryDisplay` と `rules.teacherHistoryDisplay` に記録します。
- CDAの注文板には有効な買い・売り注文を表示し、直近約定値を併記します。標準16人市場では各8行です。学生画面では「注文履歴・歩み値」を中央の独立した列にまとめ、条件・注文フォームは注文板の下に配置します。学生の履歴はCDAで設定した全期の終了済み注文と約定を、終了・成立時刻とイベント順で新しい順に1つの表へ表示します。種別は買い注文・売り注文・約定で区別し、約定済み注文は対応する約定行に統合して二重表示を避けます。学生には参加者番号を表示せず、自分の記録に「あなた」を付けます。教員には番号を残します。新着行と件数は淡い緑で2回、計2.4秒間だけ知らせ、初期表示の履歴や更新されていない行は点滅させません。動きを減らす設定では点滅の代わりに一時的な緑の背景を使います。ページ送りやタブ切替はなく、過去の記録は表内をスクロールして確認し、「最新」で先頭に戻ります。履歴は取引不可で、最良注文・撮合・スプレッドには現在有効な注文のみを用います。CDAの即時約定した入力指値は公開履歴に含めません。Callの有効注文は受付中の注文板に表示し、履歴には清算結果を残します。終了した注文は`order-closed`監査イベントと`settings.json`の市場別`orderHistory`にも記録し、公開ルールを`rules.cdaOrderHistory`に明記します。旧保存ルームは更新後に終了する注文から履歴を記録します。

この実装は `大規模実験メモ.pptx` の新版実験1を対象にしています。旧口頭実験の9人・司会者・手数料は適用しません。資料で一意に定まらない運用上の選択は、以下および教師画面・条件JSONに明記しています。原資料はリポジトリに同梱しません。

## 採用ルール

教員は作成画面の「実験時間の設定」で、CDAの1期・Call Marketの1回の受付・Posted Offerの売り手提示・買い手共通取引時間を個別に設定できます（各1〜3600秒の整数）。作成後も「実験設定を変更」→「実験時間の設定」で開始前に変更できます。Callの受付回数は標準4回、5単位設定では5回で、受付時間は5秒設定も可能です。既存ルームの時間を一律に5秒へ変更しません。共通取引時間の未指定時は従来の `buyerSeconds × 市場の買い手人数` を使います。設定値は `config.studyTiming` と条件JSONの `rules`、変更は `study-timing` 操作ログに保存します。

| 制度         | 時間                           | 注文・価格                                                                                                                                            |
| ------------ | ------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| CDA          | 180秒／期                      | 1人1件・次の1単位。価格優先、同値は時間優先。交差すると先に板にあった注文価格で約定。置換は時間優先を失う                                             |
| Call Market  | 30秒 × 4回／期（5単位では5回） | 各回1回、現在の1単位の注文価格を注文板に公開。締切でのみ一括清算。買値降順・売値昇順で成立可能数量を最大化し、最後の成立組の中間値で全件清算          |
| Posted Offer | 提示60秒＋共通80秒（16人市場） | 売り手は最初の1単位の価格を締切まで非公開で確定。約定後に次の単位を再提示。買い手は提示一覧の購入ボタンで、その売り手の提示価格を受け入れ、直ちに購入 |

- **損失が出る取引も許可**し、予定利益を表示します。Commissionは成立1単位ごとに買い手・売り手の双方へ加算する報酬です。作成フォームの既定は各1円、0円で報酬を無効にできます。供需条件の設定で入力し、現在の供需から上限を計算します。昇降順の価値・費用で最初の負の余剰の差をgとすると、2×Commission<gを満たす整数のみ許可（上限は999円とceil(g/2)−1の小さい方）。負の余剰がない条件は999円まで。Defaultと候補p=80・K=8・L=4・d=4では上限3円です。超限額は切り詰めず拒否し、人数・生成・手動の条件変更にも同じ検査を適用します。作成後も「実験設定を変更」→「供需条件の設定」で開始前に変更できます。開始後は固定されます。金額は学生の待機・条件欄に表示し、予定利益・約定通知・個人履歴・今期と累積利益に加算します。未約定・取消・出品だけでは報酬はありません。既存ルーム／既存の約定に設定・記録がなければ0円のままです。各約定に報酬額を保存するため、過去の利益を設定変更で再計算しません。価格・価値・費用・利益は実験上の円（JPY）で、実際の決済はありません。
- 教員の作成ページは設定の種類ごとに分け、広い画面では実験設定・供需条件・全単位の数値を3列で表示します（1100px以下は実験設定を上段に配置）。供需条件と単位表の領域幅が800px以上なら単位表を右側の独立パネルに置き、それ未満では下に並べます。右側の表はスクロール中も追従し、単位数が多い場合は表の枠内で縦スクロールできます。供需プレビューはCommissionなし／込みの均衡価格・均衡数量を並べ、金額変更時に更新します。Commission込みはD+c、S−cから計算し、曲線・最大総余剰・効率の基準は元の価値・費用を使います。条件と報酬は開始前に同時保存できます。
- 入力価格は1〜99999円の整数。Callの清算価格は0.5円刻みになる場合があります。
- Callは1人1回1単位です。同値は各清算時の無作為な参加者優先順位で処理します。抽選結果は操作ログに保存します。約定した場合は次の単位、未約定の場合は同じ単位を次の回で注文します。
- Callの未約定注文は清算ごとに失効し、残り数量を再注文できます。**取引済み数量は清算ごとに戻りません**。
- Callの数量選択はなく、現在の1単位だけを注文します。締切までに送信しなければ、その回は注文なしとして進み、残り数量や利益は変わりません。入力だけでは自動送信されず、次の回では再び注文できます。未送信の理由は記録から区別できません。以前の版で記録された `call-pass` は過去の操作ログとして保持します。
- 新規Postedは `studyPostedMechanism: direct-purchase-v1`。買い手は価格を入力せず、昇順の提示一覧から購入する売り手を選びます。`posted-buy` は提示IDと数量だけを送り、サーバーがその提示価格と残在庫を検査して即時約定します。同じ在庫への購入はサーバーの受付順に処理し、二重購入・在庫超過・取引可能数の超過を拒否します。同じリクエストの再送は二重約定しません。買い注文・買い気配の表示や1秒ごとの競売清算はありません。
- 旧保存ルームの `batch-bids-v1` は従来の1秒ごとの買値優先・同値抽選、上記フラグのないルームは従来のランダム逐次購入を維持します。途中で新ルールへ切り替えず、新ルールの実験は新規ルームで行ってください。条件JSONに各機構と優先規則を記録します。
- 新規Postedは売り手・買い手とも現在の1単位ずつ取引します。売り手は初回約定後、共通取引時間中に次の単位の価格を再提示でき、その提示は直ちに公開されます。買い手は約定後に次の単位の価値を確認して購入できます。再提示待ちの間に在庫が一時的にゼロになっても期を終了しません。締切までに確定しなければ、その期は出品なしで進みます。以前の版で保存された複数単位の提示や0単位の提示は過去の操作ログとして保持します。
- 途中終了は未約定注文を取消し、進行中の期を `interrupted` とします。Callの未清算注文は約定しません。既に正常終了した市場の期は `complete` のままです。
- 標準の16人市場では、既定の均衡は80円、正余剰の数量10、ゼロ余剰を含む上限11、最大総余剰440円。数量比・効率・価格偏差の基準は、設定した人数の実際の価値・費用から計算します。

条件テンプレートの人数を変えると需要・供給量やPosted Offerの共通取引時間の既定値（テンプレートの買い手人数×標準10秒）が変わります。実人数での割り当てだけでは保存済みの時間設定を変更しません。新規ルームの実人数は `config.studyLayout` を確認してください。固定人数の旧ルームは `config.marketSize` と `rules.tradersPerMarket` を使い、`marketSize` 未保存なら16人として読み込みます。

### 横向き重なり階段の候補をプレビューする

教員のルーム作成ページの「作成前に詳細を設定」では、第2ステップで人数・市場数、第3ステップの「供需プリセット」で単位数・Commission・供需条件を設定します。Defaultは既存のPPT条件を人数・単位数に合わせて均等抽出・複製したもの、カスタムはp・K・L・dから生成する別の階段供需です。教員用のデモも同じフォームを使いますが、デモのDefaultは既存の練習用条件です。カスタムのプレビューは現在の入力から自動更新され、「設定を保存して閉じる」の1回で保存します。保存後のルームは入室締切のステップから始まります。

作成後も、実験開始前なら「実験の準備」の「市場・取引条件」から変更できます。Defaultもカスタムも「確定して次へ」の1回で現在の条件を保存して次へ進みます。作成APIは採用した生成パラメータを受け取り、サーバーで再生成・検証して保存します。学生に渡す一般のルーム設定には生成パラメータ・シード・分配表を含めません。

カスタムの初期候補は `p=80, K=8, L=4, d=4` です。Defaultからカスタムへ切り替えるとこの候補に戻り、保存済みのカスタムを開き直すと保存値を復元します。人数・単位数が変わっても価格やK・Lを自動調整しません。第k単位の価値／費用は、k≤Kで `p±d(K+1−k)`、K<k≤K+Lでp、その後は `p∓d(k−K−L)` です。K・Lは1以上の整数、K＋Lは片側総単位数以下、d>0とし、生成値は1〜99999円の整数条件で検証します。候補が人数・単位数に合わない場合はエラーを表示し、保存を止めます。丸め・切り詰めは行いません。

正式版の標準Default（16人・各2単位）は、ソートした供需曲線に限れば `p=80, K=10, L=1, d=4` で完全に一致します。ただし個々の学生への2単位の組合せは生成器と異なります。100人に拡大したDefaultは均等抽出・複製により均衡価格以外にも同値の台段ができるため、固定の正の価格差dを使う現行式では完全再現できません。DemoのDefaultも価格差が一定ではないため完全再現できません。Defaultを生成式へ置き換える変更は行っていません。

カスタムでは入力と同時に階段供需図・全単位表・均衡価格・数量下限と上限・正余剰／ゼロ余剰の単位数・最大総余剰・学生割当候補を更新します。第k単位の水平線は数量k−1からkまでです。片側16単位の初期候補の均衡は80円、数量8〜12、最大総余剰288円です。L=1,4,6では上限が9,12,14になり、価格・正余剰数量・最大余剰は変わりません。

供需図は原始均衡の価格・数量区間の中点を中央に置き、初期表示ではその周辺を表示します。「拡大」「縮小」でも中心と線形の軸尺度を保ち、「全体」で全単位を表示、「初期表示」で周辺表示に戻ります。数量0未満・総単位数を超える余白には曲線を描かず、背景色で区別します。右側の全単位表は画面の高さに収まる独立スクロール領域で、フォーカスしてPageDown・Endでも移動できます。

片側人数N・1人あたりU単位に応じてソート済みの第i、第i＋N、…、第i＋(U−1)N単位を同じ役割へ割り当てます。同じ人数の市場は同じ役割別の価値・費用を使います。実人数が違う市場には条件テンプレートを均等抽出・複製します。同じ生成パラメータから選択した各制度の単位数に応じた条件を生成し、全制度の価格範囲とCommissionを検証します。単位数はconfig.studyUnitCounts、制度別の供需表はconditionsByInstitutionに保存します。この形式のルームは逐単位注文を使います。形式導入前の保存済みルームは従来の数量・注文方式を維持し、開始前に供需設定を保存すると新方式へ切り替わります。全市場の固定席をMulberry32とFisher–Yatesでシャッフルし、入室順に学生を入れます。同じ人数・入室順・0〜4294967295の整数シードで同じ分配になります。候補シードの初期値は123456です。保存済みルームのシードは変更しません。

「確定して次へ」を押すまで現在のルーム条件は変わりません。保存時にサーバーでも再生成・照合し、価値・費用を既存の設定欄に保存します。保存後は入室を締め切り、実人数での分配を確認します。旧固定人数ルームは「ランダムに割り当て」で確認します。同じシードでの再割当は同じ結果になります。再抽選したい場合は開始前にシードを変更してプレビュー・保存してください。設定JSONの `generation` に候補パラメータ・シード・適用日時・確定日時・最終分配表（参加者ID、名前、市場、席、役割、対応単位、価値／費用）を保存します。開始後は条件と分配が固定され、全期・全制度で維持されます。手動編集やPPTへの復帰は生成メタデータを解除します。

均衡数量は区間で扱います。ゼロ余剰の取引を含むQ/K>1を自動的に過剰・非効率とは判定しません。最大余剰はソート後の単位ごとの正の価値−費用の合計、実現効率は実現余剰との比、非効率取引数は価値<費用で計算します。正式採用するLとシードの再利用方針は教員が決めます。

## 収束とデータ出力

価格を均衡に強制的に近づける処理はありません。教員画面で市場・制度・期ごとに以下を表示・出力します。

- 平均価格、均衡価格区間までの平均絶対距離。
- 価格偏差 `α = sqrt(mean((価格 − p*)²)) / p*`。`p*` は均衡区間の中点。表示は比率であり百分率ではありません。Callも全4回の個々の約定を数量加重で含みます。
- 各制度で設定した期数に対するαのOLS傾き。正常完了し取引がある期だけを使用し、対象期数も記録します。これは記述統計で、有意差検定・自動収束判定ではありません。
- 約定数量と `Q / Q正余剰`。ゼロ余剰の取引により比率が1を超える場合があります。
- 実現総余剰、最大総余剰に対する効率、`価値 < 費用` の非効率取引数。
- CDAの最良売値−最良買値の時間加重平均。両側に注文が存在する時間だけを対象にし、一時停止時間を除外します。観測時間も出力します。

取引ゼロの価格統計、分母ゼロの比率、観測時間ゼロの気配差は `null`（画面では「—」、CSVでは空欄）です。余剰は価値−費用で計算し、Commissionを含めず、損失を0に切り上げません。均衡・最大総余剰・効率の供需基準は変えません。Commissionの支給総額とCommission込みの参加者利益合計を別途出力します。

取引CSVに市場、制度、全体期、制度内期、清算回、双方の単位番号、価値・費用・Commission込みの利益、Commissionを除く利益、片側1単位のCommissionを含めます。集計CSV、操作ログCSV、条件JSONも保存できます。日時はUTC、画面は日本時間。条件JSONに全市場の制度順、条件、採用ルール、期の完了区分、清算結果、指標を含めます。認証情報は出力しません。

## 旧形式のルーム

以前の3商品CDAルームは従来のルールで継続・再入室できます。新規作成の標準は実験1です。旧形式を明示的に作る場合は `/teacher?legacy=1`、その説明は `/guide?legacy=1` を使います。
